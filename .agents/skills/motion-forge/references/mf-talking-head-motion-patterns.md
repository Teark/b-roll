# 口播包装：容器、遮罩与动作因果

用于人物在全幅与卡片间转换、身后文字、拖拽揭示、选择卡片、知识卡列与身后海报轮播。方法整理自五组口播教程；可读 [公开教程分析结果](../../../../reference-library/analysis/tutorial/rl-talking-head-methods.md)，原视频与转写不随开源包分发。该报告是历史分析，不代表本次观看；下面保留独立可用的实施方法。以下是对本项目的实施规则，尚不是已经实现或验收的组件。内容适配由 [SRT 场景选择](../../srt-brief/references/sb-packaging-pattern-selection.md)负责。无需为不涉及这些机制的修订加载本文。

## M01 先定可读终态，再反推进入状态

教程多次从“第二个关键帧”开始：先摆好最后的位置、大小和关系，再回到开头设置隐藏或缩小。本项目借用这个单段设计顺序，不强制恰好三个关键帧，也不先把整片排成静态终态合集。composition 先定代表性关键构图，完整读取 animation 后先做通连续样段，再将此方法逐段用于构图与动画。

先在交付相机下做成稳定状态：人物、真实文案、卡片数量、图像裁切与安全区都成立；随后确定来源、遮罩边界、进场路径、停稳和退出。字幕再长也不能靠压缩最终阅读窗口解决。复用卡片时共享样式与动作规则，内容、裁切、身份和出场时间独立。

## M02 将轮廓变化、内部取景与容器移动分开

人物由全幅变圆角窗再变小圆，涉及三个不同变量：

- 外部容器：屏幕位置与占位大小。
- 遮罩：宽高、圆角、揭示边界。
- 内部视频：保持比例的裁切、脸部锚点和画面取景。

可先在同一局部坐标系内改变遮罩，再由父级将整体缩入目标位置；也可以交叠两段动作，但不能让蒙版和内容各自漂移。正方形圆角半径达到边长一半才成为圆形；只有圆角变大而宽高仍不等，会得到胶囊。人物不得随容器宽高非等比拉伸。换父级或合成层时匹配交接两侧的屏幕投影。

**内部取景必须重新构图，禁止只对视频矩形做居中 cover。** 每种目标窗形先在真实源帧中定位完整头部、面部中心、肩部及必要手势；以人物视觉中轴对齐窗口水平中线，保持等比，联合求内部缩放与水平/垂直偏移。脸的位置跟随人物，不沿用源画面中心或上一种窗形的固定裁切。头顶留白，脸、下巴和颈肩完整衔接，不能让边界压住脸或截在脖子上。不要为填满窗口过度放大，也不要留下大片空白把人缩成小头。

在目标窗内无法同时满足时，扩大窗口、调整宽高比或降低内部放大倍率；源人物靠画边/硬字幕压身时按实际可用画面重排，不虚构缺失身体，不用随机裁切凑满框。原景保留时，内部视频与人物alpha必须共享这一套取景；单独移动透明人物会留下底轨第二张脸。允许裁切窗口内留出设计留白来容纳源内容，不能牺牲脸部完整和居中。

动画把外部移动、遮罩形变和内部重构图作为协同但独立的变量。先让目标人物构图成立，再从原取景连续过渡；在开始、中途、形状最窄、人物运动极值和停稳检查实际画面。使用关键取景或平滑的人物跟踪，不能逐帧追脸抖动，不能为了最后一帧居中而在中途扫过脸或卡住脖子。小窗放左下还是右上只改变外部位置，不取消框内居中。

人物视频卡片的投影、边缘受光与层间分离按 [S04 光影与悬浮](mf-space-camera.md#s04-光影和清晰范围支持关系) 同步变化；阴影在卡片遮罩外绘制，不能随内部裁切被切没。教程中的“复合片段”迁移为共享局部坐标、裁切或效果边界，不意味着每层都增加离屏渲染。

## M03 将拖动对象、边界与揭示绑定到一个事件

拖拽分隔线时，指针接触点、手柄、线和遮罩边界由同一个进度驱动，接触后的相对位置保持稳定。框选展开时，框角、虚线终点与内容揭示共享几何；松开后才恢复自由指针移动。不能让鼠标追赶一个自行展开的页面。

点击模式区分“靠近 → 落在目标上 → 点击反馈 → 内容响应”。点击声若使用，落在点击事件；不在指针尚未到达时提前换内容。具体容许延迟由观看结果决定，不虚构参考原工程帧级参数。

## M04 用同一对象完成总览到详情的交接

关系环上的成员可以从自己的位置扩大为详情卡，再回到原位置；缩略图与大图使用同一内容身份。保留能让人确认“选中的是谁”的位置、形状或高亮关系。总览成员数由实际内容决定；环形/网格位置可计算，逐项保留真实裁切。

装饰性慢旋转不等于环绕公转。源教程演示了圆图自转，不应据此添加整环公转或三维相机环绕。真人表情需要辨认时，可减弱旋转或只让外框运动。

## M05 人物出框只增加需要的轮廓

圆角窗保留原片背景时，框内人物不描边。同步透明人物只扩展需要出框的头部/手势，不复制第二个人物；越界部分背后已换为设计背景时，仅在这部分轮廓显示描边，不能沿整个人物补一圈边。原片、人物、条件性描边共享时间、缩放、裁切与位置；局部遮罩同时限制人物与描边的越界范围，避免腰部重复显露。统一按 [背景判定表](../../srt-brief/references/sb-talking-head-lessons.md#参考分工与人物层) 执行。

从全幅转到小窗时，原位置的背景人物必须在交接中被遮住或正确退出。检查运动峰值和遮罩经过脸部的位置，不能只检查落定画面。茶叶案例的过渡帧可见重复头部/横向切片，属于需要避免的接缝，不能照抄成风格。工程基础仍遵守 [口播人物分层](../../srt-brief/references/sb-talking-head-lessons.md)。

## M06 错峰与缓动服务信息次序

标题、辅助语、卡片可以错峰揭示；同一词组、数值单位不为错峰而拆散。总进入预算同时包括各项延迟及最后一项的进入时间，必须给最后一项留下可读停留。容器先建立、信息再接管是可选顺序，不是每个镜头固定公式。

教程反复使用二次方缓动，体现的是加减速与停稳，不是回弹。按动作选择 ease-in、ease-out 或 ease-in-out；需要回弹时另有表达依据。教程中的“一帧”“几帧”属于其编辑时间线，不从约 60 fps 录屏反推编辑帧率，倍速播放段也不直接提供真实动作时长。

## M07 将效果限制在实际运动层

文字上移的运动模糊随位移出现，稳定阅读时恢复清晰；标题快动不应使脸和全背景一起模糊。模拟曝光的采样应在同一连续动作内，不跨硬切混合无关画面。若未取得同步子帧视频，不把静止视频纹理下的包装层采样称为整片真实运动模糊。

海报轮播可保持外容器和人物稳定，内容轻微推近并在内部切换。曝光闪变、柔化等可作为局部转场选项；只作用于卡内，不默认全画面爆闪，也不凭单帧亮斑推断原作者使用了何种算法。正文/证据需要读时减弱效果，保证停稳清楚。

## M08 材料和排版按职责适配

教程的低对比网格/点阵负责统一背景，黑白次要头像与彩色中心人物负责主次，粗标题与纤细副字负责层级，圆角/描边/阴影负责容器边界。迁移这些职责，不强制紫色、粉色、网格、黑白人物或英文装饰字。

英文展示字纵向拉伸是该案例造型；中文先选真实字重、字宽、行距及布局，避免连人物、Logo、汉字一起非等比拉伸。若设计刻意变形，在目标尺寸核对辨认度。点阵与虚线在手机尺寸检查闪烁、摩尔纹和对比，制作标线/选框只在本片确实讲操作时出现。

## M09 小圆头像与平台安全区由一条派生线控制

用户给出平台避让要求（例如“底部 20% 不出现文字，人脸也在其上方”）时，要做的是先定一条安全线、再让所有会碰到它的尺寸由它算出，不是把排好的元素逐个往上挪。

```text
SAFE_Y  = 画幅高 × 避让比例        // 1080×1920、20% → 1536
AV_R    = 头像半径                // 由画幅宽度比例定
AV_Y    = SAFE_Y − 边距 − AV_R     // 头像圆心
PANEL_H = SAFE_Y − 边距 − PANEL_Y  // 面板高度由安全线反推
```

头像半径与圆心、面板高度、标签条基线、导轨与进度终点都只引用这些派生量。改比例时整片一起变，不会出现“头像已经抬高、面板下沿还压着安全线”的半途结果。面板高度是派生结果而不是输入：内容变多时先减行距、按语义换行或分时呈现，把余量还给安全区，不靠压字换取更高的面板。安全线约束人脸与必读文字，背景、纹理、装饰仍可满幅出血。

圆形头像的三个变量与 [M02](#m02-将轮廓变化内部取景与容器移动分开) 相同（外部容器、遮罩、内部取景），但圆形多一个坐标陷阱：WebGL 层的遮罩若按纹理 UV 算距离，2D 层的盘面按画布像素画，非正方形取景下两者会错开。统一按画布像素算——用片元的画布坐标与画布上的圆心、半径比较，遮罩与盘面就天然同心，不需要再补一个经验偏移。

头像形态一旦固定就不逐章变化：开场由略小的半径弹到目标半径一次，正片保持同一尺寸（除既定的换边）。每章推近、收放会让观众反复重新定位讲述者，并逼着依附它的标签条反复改距。

换边按语义段计数、每两段一次，且换边落在切点：旧位置持续到该段切点，新位置从画外滑入约 0.30s 到位，不做横穿画面的平移。标签条、引线由“头像当前在哪一边”派生，换边后自动走到反面；附属元素写死坐标就会在换边后压在头像上或留在半空。

1080×1920 逐帧截图有明确预算：Canvas 的 `filter`（尤其多层 drop-shadow）和 `shadowBlur` 会把单帧渲染拖到截图超时。软投影改为在盘面外圈预绘径向渐变，发光改为低透明度同心填充；截图变慢先查效果开销，不要先怀疑浏览器或编码器。

交付前对成片做整片像素统计（裁出安全区、导出灰度帧流、逐帧计数），不要只抽几张终态帧；抽帧全绿不等于全程不越界。

## 在当前工程中怎样落地

可在本次新工程中采用 Canvas 内容层、Three.js 平面/合成及绝对时间渲染。按下表实现需要的关系，不读取旧片源码，也不假设下列成品接口已经存在：

| 教程机制 | 可选实现 | 必须看到的证据 |
|---|---|---|
| 复合片段 | 共享父级、Canvas 局部变换；需要组级滤镜时才离屏合成 | 图片、标签、边框随整体一致移动 |
| 圆角与圆形变换 | 外容器、遮罩、人物锚点驱动的内部等比取景分别控制 | 中间态不扭脸、不漏底；人物居中、头部完整、颈肩不被边界截断 |
| 鼠标拉线 | 单一时间进度求边界，再派生指针接触点与线 | 运动过程中接触关系不脱离 |
| 多项错峰 | 按语义事件求各项局部时间，不依赖逐帧累计 | 随机跳时与顺播状态一致 |
| 人物出框 | 同步底轨、人物 alpha 与按背景条件启用的描边，独立越界遮罩 | 原景区域不描边，换背景轮廓才描边；遮挡正确且没有第二张脸 |
| 人物悬浮卡片 | 容器外部投影、边缘受光/厚度/透视与焦点关系 | 卡片在最终尺寸明显离开底面，运动时光影关联；人物描边不能代替 |
| 固定框轮播 | 容器常驻，内容裁切、纹理与局部效果变化 | 换图时框位与人物锚点稳定 |
| 小圆头像 + 平台安全区 | 由安全线派生半径、圆心、面板高；遮罩与盘面按画布像素同心 | 整片没有人脸或必读文字越线；换边在切点完成，附属标签跟随到反面 |

验收只检查本次选用的关系：可读终态、连续中间态、人物同步、指针接触、声音落点（若有）和目标画幅。看到了静帧只能证明静态关系；此教程分析不替代未来成片的动态验证。
